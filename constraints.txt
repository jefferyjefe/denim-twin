# constraints.txt -- the exact version of every package in the dependency closure.
#
# WHY THIS FILE EXISTS
# ---------------------------------------------------------------------------------------------
# Both requirements files begin with `-c constraints.txt`, so `pip install -r requirements.txt`
# and `pip install -r requirements-ci.txt` are fully pinned without anyone having to remember an
# extra flag. Two consequences, and both are the point:
#
#   1. TRANSITIVE dependencies are pinned too. Pinning only the twelve packages we name by hand
#      still lets scikit-image pull a different imageio next Tuesday. A run whose numbers depend
#      on which day it was installed is not reproducible, whatever its top-level pins say.
#
#   2. requirements.txt and requirements-ci.txt necessarily list the seven shared core packages
#      twice -- they have to, because they install different OpenCV BUILDS (see the OpenCV note
#      below). If those two lists ever disagree on a version, at least one of them disagrees with
#      this file, and pip aborts with a constraint conflict. The failure this repository actually
#      had -- two unpinned lists quietly describing two different environments, for months, with
#      nothing recording which one a given result came from -- is no longer expressible.
#
# PROVENANCE OF THESE NUMBERS
# ---------------------------------------------------------------------------------------------
# Every version below was read out of the maintainer's working virtualenv with
#
#     .venv/bin/python -m pip list
#
# on this step (CPython 3.9.6, macOS arm64). These are the versions the artefacts currently under
# reports/ and experiments/ were produced with. Nothing here was picked off a changelog or a
# release page; nothing here is a version that has not been observed running this code.
#
# The closure was COMPUTED from installed package metadata (walking `Requires-Dist` with the
# environment markers evaluated), not eyeballed off `pip list`. Packages that are present in that
# virtualenv but not reachable from the twelve declared dependencies -- pdfminer.six, cryptography,
# cffi, pycparser, charset-normalizer -- are deliberately NOT pinned here. They are not ours.
#
# A constraint on a package that nothing requires is a no-op: it caps a version, it never installs
# one. That is why the whole closure can live in one file that both environments share.
#
# WHEN YOU CHANGE A PIN
# ---------------------------------------------------------------------------------------------
# Bump it here, re-run the verification in docs/REPRODUCIBILITY.md, and say in the commit message
# what moved and what it changed. A pin that is bumped without a re-run silently detaches the
# committed numbers from the environment that produced them.

# OpenCV. Both distributions are pinned to the SAME upstream OpenCV release, on purpose: exactly
# one of them gets installed (requirements.txt takes the GUI build, requirements-ci.txt the
# headless build), and pinning both here means the choice of build can never become a choice of
# OpenCV version. They ship the same cv2 module from the same source; the headless build simply
# omits HighGUI, which a CI runner has no display for anyway.
